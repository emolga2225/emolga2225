3. ROOT CAUSE OF OVERFITTING - "EXCESS PRECISE DATA"
================================================================================

PRIMARY CAUSE #1: Deterministic Label Generation
  Location: match_stems_framewise.py (lines 61-106)
  Problem:
    - Frame-by-frame matching uses HARD frequency threshold (100 Hz)
    - Binary decision: match OR no-match (score > 0.1)
    - Same sinusoid → always same stem label (deterministic)
    - Real world has ambiguity; model given FALSE certainty
    - No soft labels, no confidence scores

PRIMARY CAUSE #2: Data Augmentation Gap
  Location: preprocess_training_data.py + train_stem_separator_fast.py
  Problem:
    - ZERO data augmentation applied to features
    - Frequencies, amplitudes, phases unchanged each epoch
    - Window overlap (50%) means same frames appear multiple times
    - Window stride=16, size=32 → frames 1-32 in window 1, 
                                    frames 2-33 in window 2, etc.

PRIMARY CAUSE #3: Window-Level Filtering
  Location: preprocess_training_data.py (lines 73-78)
  Problem:
    - Skips windows with >50% unmatched frames
    - Only includes "easy" well-matched data
    - No hard negative examples for model to learn from
    - Biases toward overconfident matching

SECONDARY CAUSE #4: Insufficient Regularization
  Issues:
    ✓ Dropout: 0.1 (very low)
    ✓ Mask-based filtering
    ✗ NO L1/L2 weight decay
    ✗ NO batch/layer normalization
    ✗ NO mixup/cutmix
    ✗ NO label smoothing
    ✗ NO early stopping mechanism
    ✗ NO validation set (100% train, 0% validation)

SECONDARY CAUSE #5: Learning Rate Instability
  Git history shows: 1e-3 → 5e-3 → 1e-2 → 5e-3 → 1e-4
  Indicates: Multiple unsuccessful tuning attempts
  Effect: No stable convergence, overfitting became harder to control

8. KEY FINDINGS SUMMARY
================================================================================

Root Cause of Overfitting:
  The combination of:
    1. Deterministic hard-threshold label matching (no uncertainty)
    2. Lack of data augmentation (identical features each epoch)
    3. Window filtering that excludes hard examples
    4. No regularization beyond minimal dropout
    5. No validation set to detect overfitting

This creates a "too clean" training set that doesn't represent
the real variability in sinusoid matching.

Evidence from Git History:
  - Multiple learning rate adjustments (1e-3 → 5e-3 → 1e-2 → 1e-4)
  - Indicates developers noticed overfitting issues
  - Attempted solutions: class weights, learning rate reduction
  - No systematic approach to addressing root causes

================================================================================
CONCLUSION
================================================================================

The overfitting is caused by EXCESS PRECISE DATA combined with insufficient
regularization and no validation metrics.

The labels are created deterministically with hard thresholds, creating
false confidence. Combined with no data augmentation and selective window
filtering, the model sees a "too clean" representation of sinusoid-to-stem
mapping that doesn't reflect real-world variation.

Solutions require changes at multiple levels:
  1. Data generation: Soft labels with uncertainty
  2. Data preparation: Include hard examples, add augmentation
  3. Model training: Add regularization, validation split

The most impactful single change would be soft-label matching with confidence
scores instead of binary labels.
